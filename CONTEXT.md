# ModernWigiDash: Domain Glossary & Architecture

## What this project is

ModernWigiDash is a .NET 10 WPF application that drives a USB-connected small LCD display (G.Skill WigiDash, VID 0x28DA PID 0xEF01, 1016×592 pixels, RGB565 framebuffer). The application composites customizable widgets (clocks, weather, hardware telemetry, Twitch chat, stock tickers, etc.) onto pages and streams the rendered frames to the display over USB HID/WinUSB.

## Domain Glossary

### Core Concepts

| Term | Definition |
|------|-----------|
| **WigiDash display** | The physical 1016×592 RGB565 LCD connected via USB HID (WinUSB or LibUsbDotNet). Manufactured by G.Skill. |
| **Widget** | A self-contained UI component displayed on the WigiDash canvas. Each widget has a metadata attribute (`[WidgetMetadata]`), renders via SkiaSharp to an `SKCanvas`, and receives touch input. Widgets are registered by reflection and instantiated by `WidgetPluginLoader`. |
| **Page** | A layout container holding placed widgets. The profile holds ordered pages; users swipe between pages at runtime. |
| **PlacedWidgetInstance** | A widget bound to a position on a page, holds coordinates, size, rotation, opacity, and the widget instance. |
| **Profile** | The persisted set of pages, active page index, and widget placements. The page-range invariant is enforced at the type: the `Pages` setter repairs a null/empty assignment to a default page and the active index is clamped on write (re-clamped on read), so `ActivePage` is total. The old orphan-page fallback (a detached page whose mutations were silently lost) is unrepresentable. |
| **Frame** | A pixel buffer (SKBitmap) composited by `SkiaFrameCompositor`, converted to RGB565, and streamed to the display over USB. |
| **FrameSink** | ~~A destination for composited frames: `IFrameSink` exposes `SendFrame(SKBitmap)` + `IsReady`, returning a truthful `FrameDeliveryResult`.~~ **Removed (ADR-0005)**: the WCF sink and `FrameSinkRouter` were removed with the Service. The App binds one `FrameDelivery` instance to the direct-USB engine (see the `FrameDelivery` row). |
| **FrameDelivery** | The single frame-delivery policy module (Sdk): bounded DropOldest channel → drain-to-latest → paced send, owning encode, an exact-size buffer pool sized from the encoder's output (self-sized by construction, a pool that disagrees with the encoder is unrepresentable), and drop accounting. The send seam returns the truthful `FrameSendResult` (Sent / Refused / Failed), so the delivery's accounting splits a device refusal (`SendRefusedCount`, no live connection, or the frame fails the transport's size contract) from a broken pipe (`SendFailedCount`). The two no longer share one bool, and both are distinct from drops. One entry point feeds the policy: `Push(SKBitmap)` (encode + pool, void: the drop verdict is observable through the counters, not returned per call); a `FrameDelivery.Create` factory makes the required encode/pool/send seams unrepresentable at production bind sites (the ctor remains for tests exercising unconfigured readiness). The App's direct-USB sink is its one runtime instance; pacing defaults to 33ms, the USB engine's device-capability rate. Drop counting lives inside the module, split by reason (`DroppedUnconfiguredCount`, `DroppedNotReadyCount`, `DroppedPoolCount`, `DroppedCoalescedCount`, `DroppedEncodeCount`) under the `DroppedCount` total, and the drop verdict is observable: pool-exhaustion, coalesced-backlog, and post-dispose drops log through the same injected seam at first-plus-every-60th cadence (the production bind site passes its FileLog sink), so a wedged pipe that drops frames is visible in the display log. |
| **DisplayGeometry** | The WigiDash framebuffer geometry (Sdk), the single source of truth for the active pixel area (1016×592, 2 bytes/pixel, payload size). Hardware's `DisplayProtocolConstants` aliases these values and Core's compositor derives its buffer from them, so the pixel area can never drift between projects. |
| **FontCacheEviction** | The font-memoization overflow-bound rule (Core/Rendering): every FontHelper cache keyed by content variety (glyph presence, fallback typeface, text-run splits, cached fonts) is bounded by the same coarse reset, strictly over its own declared cap, clear the whole cache and let it refill on demand (no LRU; every entry recomputes, so an evicted entry costs one recompute). Each cache's cap is declared exactly once in the module (`GlyphPresence`/`FallbackTypeface`/`TextRuns`/`CachedFont` limits), so the four bounded caches can no longer drift from one another or from the tested boundary (`FontCacheEvictionTests` pins the exclusive greater-than boundary and the whole-reset eviction). |
| **IRgb565Encoder / SkiaRgb565Encoder** | The encode seam (Sdk/Hardware): `IRgb565Encoder` exposes `OutputBufferSize` + `Encode(SKBitmap, byte[]). The delivery pipeline encodes through it, and its output size sizes the delivery's buffer pool; `SkiaRgb565Encoder` is the production adapter over `FrameEncoder`. Tests inject scriptable fakes, so frame delivery is testable without pixels. |
| **ConnectProvider** | One connect attempt in `DisplayHidTransport.Connect`'s provider loop (Hardware): `TryCreate` opens the device and returns the backend (or null when that driver stack cannot provide one). The record carries only the leg's identity, the diagnostic `Tag` (the file-log vocabulary the loop and the leg bind into their `DiagLog` instances, so no line hand-bakes its tag), the display name, and the leg's success line; the loop spells its own position-aware failure lines from the tag, so vocabulary cannot drift between provider and leg. The default list holds the WinUSB provider first and the LibUsbDotNet fallback second; tests inject fakes through the single `ProviderFactories` seam, including a fake LibUsb leg, to drive the connect fallback policy without hardware. The LibUsb leg's device lookup is itself injectable (`LibUsbDeviceProvider`), so its open/config/claim/endpoint teardown is scriptable; every leg failure disposes the LOCAL device, never the adopted global backend (the orphan rule). The connect path's diagnostic vocabulary (leg steps, init sequence, backend failure lines, the engine's connect machine) is one `DiagLog`-bound tag per step/area. No call site composes its own `[TAG]` prefix. |
| **WinUsbApi** | The WinUSB/SetupAPI P/Invoke surface as an injectable delegate bag (Hardware, the PresentMonNative precedent): production binds the real externs once via `WinUsbApi.Default`; tests inject managed fakes, so `WinUsbBulkDevice.Open`'s failure and cleanup paths are scriptable without hardware. |
| **Render tick** | The 30 FPS `DispatcherTimer` in MainWindow that calls `Compositor.Compose()`, converts the frame to RGB565, and queues it for delivery. |

### Hardware / Transport

| Term | Definition |
|------|-----------|
| **Transport** | The USB HID communication layer. `DisplayHidTransport` picks one **ITransferBackend** in `Connect` through the **ConnectProvider** loop, WinUSB (primary) or LibUsbDotNet (fallback), and runs its connect/init/frame/touch policy against that seam; the init verdict covers the whole sequence including the blank-frame bulk write (on-device, a post-drop reconnect timed out the 1.2 MB init write at the pipe bound while every control write still succeeded. A connected verdict for such a pipe would inherit the falsehood into the engine, so the failed write fails the leg into the existing fallback → Simulated → 5 s reconnect machinery); the backends own the device-specific transfers and teardown (WinUsbBulkDevice implements the seam directly, LibUsbTransferBackend wraps the chunked-write path); each backend also owns its acquisition sequence (WinUSB's `WinUsbBulkDevice.Open`, the LibUsb `TryOpen`: find → open → config → claim → endpoint discovery → writer), so the transport's connect legs are thin binds into the provider loop and no driver-stack ownership lives in the transport. `IDisplayTransport` exposes only the live surface the App drives (Connect, SendFrame, ReadTouch, GoToStandby) and every member has a production caller. The transport's own connection truth stays a concrete-class member for test observability, off the seam (the engine's ConnectionState is the production truth). The transport names the worst-case teardown duration behind the engine's never-stall-on-close invariant as `CloseBound` (the max of the WinUSB bulk pipe timeout and the LibUsb chunked-write worst case over a full frame) and derives the engine's close budgets from it through **CloseBudgetPolicy** (`CloseBudgets`: the smaller of the designed cap and half the bound), so the invariant is a construction fact, not a cross-file pin. All operations are synchronous. No fake async wrappers. |
| **CloseBudgetPolicy** | The close-budget derivation (Hardware): given the transport's worst-case teardown bound, the engine's two bounded close waits as one record. `CloseBudgetPolicy.Create` derives each budget as the smaller of its designed cap (2 s standby / 3 s dispose) and half the bound, so a lowered pipe timeout can never leave a budget at or above the worst case, and the crossover is exact (the cap holds while the bound is at least twice the cap; below that, half the bound). A non-positive bound (degenerate: the transport's derivation is a max of positive pipe timeouts) clamps to a zero bound with zero budgets, so a degenerate input is an immediate, observable abandon, never a negative wait `Task.Wait` would throw on. The transport exposes the derivation as `CloseBudgets` and the engine's `StandbyCloseBudget` / `DisposeAbandonBudget` read it, so the never-stall-on-close invariant holds across the seam by construction instead of by a cross-file pin (`CloseBudgetPolicyTests` sweeps the bound, pins the crossover, the non-positive-bound clamp, and engine/transport agreement). |
| **ITransferBackend** | The transport's USB transfer seam (Hardware): vendor control in/out + bulk write. Two real adapters (WinUSB, LibUsbDotNet) plus test fakes, so the transport's policy is drivable without hardware and the backend choice is made once in `Connect` instead of re-decided per call. |
| **ConnectionState** | The engine's single connection truth (Hardware): `Disconnected` / `Connecting` / `Connected` / `Simulated`: one value instead of the old lockstep IsConnected/IsHardwareActive/IsSimulationMode trio callers disagreed on. The presenter gate and the USB badge read the same state. |
| **DisplayDeviceEngine** | The App's hardware engine (Hardware): owns transport connection, standby, and the 16ms touch poll. The constructor is deliberately inert, no connect attempt, no background loops (construction never reaches for hardware, so test hosts are safe); `Start()` begins the initial connect, the 5s reconnect timer, and touch polling. The connect machine is drivable end-to-end through the transport factory (the internal test ctor wires the factory to the injected transport plus an explicit initial ConnectionState, so even a Start()-triggered reconnect routes through it); the touch loop's failure observer logs instead of going silent. Close never stalls: the standby and dispose close paths wait bounded budgets (`StandbyCloseBudget`, `DisposeAbandonBudget`) read from the transport's `CloseBudgets` (the **CloseBudgetPolicy** derivation of its `CloseBound` worst-case teardown), so they stay strictly shorter than the worst case by construction rather than by a cross-file pin, abandoning a hung device's handle at exit rather than freezing on it. The standby verdict is read from the task's `Result` only once `Wait` confirms completion (`Task.Wait(timeout)` reports completion, not the result, the 2026-08-21 trap that turned the verdict line into dead code), so a not-confirmed standby, an expired bounded wait, and a throwing standby each leave their own `[STANDBY]` line. `SendFrameBytes` is the liveness guard (disposed / not connected / no adopted transport / null buffer) that relays the transport's verdict. The frame SIZE contract belongs to the transport alone (the engine forwards what it is handed, so the size rule has one owner). |
| **FramePump** | The 30 FPS presentation cadence module (App): dispatcher timer that composes the active page, pushes the frame into the window's FrameDelivery (the compose gate reads the delivery's `IsSendInFlight` directly), and requests a repaint. The window keeps only the WPF draw, so the buffer drawn is exactly the buffer sent. Badge refreshes ride the tick as an injected callback. |
| **FrameEncoder** | Converts SKBitmap (RGBA) → RGB565 little-endian byte array for the display's framebuffer format (BGRA/RGBA fast paths + per-pixel fallback, shared `PackRgb565` bit packing; handles scaling when the source bitmap isn't exactly 1016×592). The single bit-packing owner behind the **IRgb565Encoder** seam. |
| **TouchReport** | Hardware touch input from the display: type (Down/Up), X/Y coordinates. Polled by the App's `DisplayDeviceEngine` at 16ms in direct-USB mode and normalized once via the shared `TouchReport.ToEventType` (the single mapping site, also used by the deleted Service seam). The App never sees vendor protocol bytes. |
| **DisplayProtocolConstants** | USB vendor commands, framebuffer dimensions, and protocol constants for the WigiDash hardware. |
| **WinUsbBulkDevice** | Raw WinUSB P/Invoke wrapper for bulk and control transfers. Owned lifecycle (opens SetupAPI handle, initializes WinUSB, manages pipe timeouts). |
| **SystemTelemetryPresentation** | The Hardware Monitor widget's display rules (Widgets): the three unavailable placeholders, the label/unit override resolution, the unknown-mode → Gauge fallback, the clamped invariant-culture hero value, the gauge/bar maximum resolution with its value-derived floor, and the 0..1 progress clamp. The widget's render methods are thin adapters over it. The display is assertable without pixels (its math moved out of the widget with it; the presentation recomputes the value string per Build, so the widget's old per-value format memo is retired). |
| **TrustedUriPolicy** | The shell-open trust rule (Sdk): a host is trusted for the Twitch device-auth browser open only when it IS the twitch.tv apex or a dot-prefixed subdomain. A suffix check would admit attacker-registrable lookalikes (faketwitch.tv). One policy shared by the App's `TrustedBrowserUri` and the Widgets' auto-open guard, so the two sites can never drift. |
| **DisplayFormat** | The display-rules culture contract (Widgets): invariant, zero-aware number formatting (`Fps`/`Ms`/`Pct`/`Count`/`Number`) that every presentation module routes through. One locale contract pinned and tested once instead of per-module interpolation with the ambient culture. |
| **WeatherQueryKey** | The weather cluster's resolution identity (Widgets, ADR-0006): the ONE spelling of "which place was this weather resolved for". `Build(WeatherLocation)` is the only key construction: six identity fields (`LocationType|Location|Latitude|Longitude|CountryCode|LocationMatch`), backslash-escaped, `|`-joined (a separator inside a field can never forge a colliding key; `CustomLabel` is deliberately absent so a label edit never re-fetches); `SameKey` is the only predicate (ordinal, null-safe, case is identity). `KeyPropertyNames` / `InvalidationProperties` / `LocationMatchProperty` declare the field sets once, and `WeatherDisplayState.ResolutionInvalidationProperties` aliases the set so the widget's drift test pins it to the record. Every guard site routes through it: the client's capture window (the named **CaptureWindowGuard**, re-validated at save + return), the cache-load identity stamp, and the fetch flow's location-snapshot key + return→apply live re-check (`WeatherFetchFlow`, ADR-0007, the module captures ONE location snapshot per run, so the key and the fetch resolve from the same record), so the stale-identity invariant is assertable in one place, with no pixels and no fetch mocks (`WeatherQueryKeyTests`). |
| **CaptureWindowGuard** | The ADR-0006 capture window as a named value (Widgets): one start key captured before the fetch await + a live-key source, with `StillCurrent()` (the ADR-0006 predicate against the live key) and `Dropped => !StillCurrent()` the only two verdicts. The client builds one per fetch (live source: the fetch control's `LastLocationQuery`, so the post-save re-validation and the return→apply re-check read the same window) and the fetch flow builds one per run (live source: the host's coerced location), so "is the identity I fetched for still the identity the UI shows" has one predicate at every site instead of a hand-composed compare (`CaptureWindowGuardTests`). |
| **WeatherLocationResolver** | The weather geocoding decision policy (Widgets): candidate ranking/scoring, suffix + diacritic-insensitive matching, population tiebreak, the ambiguity gate, alias tables, postal routing (`TryPostalRoute`: numeric 2–10-digit or hyphenated n-n queries read as postal, US-default route unless a country hint is present; alphanumeric codes REQUIRE a hint. A US-guess for an un-hinted foreign code is a coin flip; `NormalizePostalLookup` keeps the indexed shape: US ZIP+4 → 5 digits, GB/CA/IM/je/gg full codes → 3-char short forms; the geocoder search runs the geocoder's maximum `count=100`. The default top-10 hid the user's city from the pick list), the response-aware weak-ISO fallback (a code match earns the weak bonus only when the state candidate is absent from the response), the ONE exact-name predicate (`IsExactNameMatch`: the pick list offers only candidates that BEAR THE NAME THE QUERY TYPED, and a persisted Location Match pick is promoted on a fresh geocode by that same rule: the live geocoder is fuzzy, so its rows can carry places the query did not name, a "Vitória" inside a "Victoria" search, and such a row is searchable (`SearchCitiesAsync` keeps every row, deliberately) but unpickable and un-promotable; a persisted fuzzy pick left over from before the rule silently re-ranks to the city the user typed instead of resurrecting the wrong-city weather on restart), and the coordinate + label rules (`TryParseCoordinatePair` / `IsValidCoordinate` / `FormatCoordinates`, `ComposeLabel` / `ComposeZipLabel`, moved from the geocoder so the transport owns only HTTP + parse). The pure decision layer behind `WeatherGeocoder` (a leaf utility `WeatherClient` also calls directly for the forecast URL and the postal route decision). Every city-resolution fix commit's rule lives here with its comment. The cluster also uses `Core.Rendering.FontHelper` for the shared font cache, like every other widget. |
| **WeatherClient** | The weather fetch/cache/resolution orchestrator (Widgets): the `WeatherFetchResult` outcome union (each `Fetched`/`Tie`/`Stale` carries the `QueryKey` it was resolved for, the ADR-0006 carried key, pinned at the client's boundary; `Fetched` is fresh at the completion of the WHOLE capture window, through the cache write: the client re-validates after its save await, so an invalidation landing in the save window converts the verdict to `Stale`, the capture window itself being the named `CaptureWindowGuard`, whose `Dropped` predicate the three re-validation sites share), and the explicit-coordinates/postal/city/pick resolution legs delegating decisions to `WeatherGeocoder` (the postal leg routes per the resolver's `TryPostalRoute`, so ZIP input is not US-only), plus the snapshot assembly. The no-coordinates verdict splits a tie from a failure (ADR-0009): a `WeatherResolutionOutcome.Ambiguous` with candidates reports `Tie(candidates, queryKey`). The tied candidates (the widget's Location Match dropdown) ride the outcome instead of collapsing into a bare `Failed` dead end, so the dropdown's documented escape route is populated on the first fetch of a tied city; an `Unresolved` search and an empty-candidate tie stay `Failed`. Both still stamp the 5-minute cooldown, so a tied city never re-geocodes at frame rate. The fetch-control state machine (5-minute throttle window, single-flight claim, resolved-identity stamp, the mutable twin of the widget's gated `WeatherDisplayState`; both twins hold the shared `WeatherResolutionState` and route their drops through `WeatherInvalidation.Drop` via their single gated `Invalidate(kind)` entries) lives in `WeatherFetchControl`; the cache file mechanics in `WeatherCacheStore`; the response parsing in `WeatherForecastParser`. The display strings never live here (that is the cluster's presentation modules'), and `LoadCacheAsync` documents its state-commitment: a successful load commits the cache's resolved identity + throttle into the fetch-control state, so a caller that DISCARDS the result must roll it back through `Invalidate(kind)` (the `Coordinates` kind). The interface says what the load did, so the rejection is the caller's job (the fetch flow enforces the rollback); the flow's own post-await re-validation guards only the return→apply gap the client's window cannot see. The throttle-stamped fact is exposed as the named `HasFetched` predicate (the flow's cadence gate reads it. Callers never compare the raw timestamp against `DateTime.MinValue`). |
| **WeatherCacheStore** | The weather cache file module (Widgets): the 1 MB size bound, the lazy name provider, the bounded stat-then-read load with the mid-read-growth guard, the identity stamp (`LocationQueryKey`) each snapshot is saved under, the atomic temp-file save, and `Clear()`. `WeatherClient` owns the staleness decision and applies the returned `WeatherCachePayload` only when the stamp matches the current query key. |
| **WeatherForecastParser** | The Open-Meteo response parser (Widgets): the modern-vs-legacy shape handling (`current` vs `current_weather`, `weather_code` vs `weathercode`), the humidity's current-block provenance (the hourly array's first bucket is stale-by-hours), the invariant day-name formatting with the "Today" marker, and the fetch-limit capping. `WeatherClient` keeps snapshot assembly and calls these pure rules per block. |
| **WeatherForecastLimits** | The fetch-limit constants (Widgets): `MaxFetchDays` / `MaxFetchHours`, the one place the forecast row caps are declared: the parser's strips and the cache store's deserialization both cap through it. |
| **WeatherFetchFlow** | The weather fetch-flow module (Widgets, ADR-0007): the SEQUENCE around one fetch: the location snapshot captured ONCE before the await (the key and the fetch resolve from the same record, so no seam read can drift between them, the former outcome-key vs. start-key comparison was tautological under one snapshot and is deleted; the client's carried key stays pinned at the client's boundary), the post-await live re-check against the live location (the client's `Stale` verdict covers the client's own window; the live re-check is the drop gate for an identity change the client's state does not see, a silent reassignment, the post-`InitializeAsync` profile hydration, verified for `Fetched` and the tie's `Tie` outcomes, ADR-0009), the drop-and-refetch routing (a dropped result force-refetches the new identity immediately, the in-flight claim that swallowed the edit-time force refresh is released by the completion), the resolved-label write-back gating (the `WeatherDisplayState.WritebackEligible` policy, the non-empty name, the CustomLabel veto, the no-op write, applied at the queue and re-evaluated under the display-state gate at the take, so a CustomLabel or Location edit landing after the queue is seen at the take, never sailed through an ungated flush check; the identity re-check at the set is one critical section), the tie apply (a `Tie` outcome rides the host's `TryApplyTie` seam: the gated candidates apply, the placeholder reset of the data state, and the `AppliedTie` verdict, ADR-0009), the single cadence gate (`CanFetch`: the static-snapshot veto once a fetch stamp exists, else the client's throttle window; force always eligible), and the boot-load rollback (the boot load takes the same one-snapshot rule; a discarded cache load rolls the client's committed identity state back through `Invalidate(kind)`; a version-only skip leaves nothing to undo). The widget keeps only host concerns, the property coercion (`BuildLocation`), the gate around the display state (owned by the `WeatherDisplayState` module, the widget's seam bodies are forwards), the UI-thread write-back flush, the context requests, and passes them across the typed `IWeatherFetchHost` seam (ADR-0008: the `CurrentLocation` coercion, the gated `TryApply(WeatherApplyRequest)`, the gated `TryApplyTie(candidates, identityGuard)` (ADR-0009), the gated write-back queue, the version / static-snapshot / run-token reads, and the two context requests). The widget IS the production host adapter (explicit implementations; the gate discipline spelled once in the display-state module) and the flow's tests wrap the SAME display-state module the widget uses, so `FetchLiveWeatherAsync` / `LoadCachedWeatherAsync` are forwards and the capture-window order (key captured before the await into the named `CaptureWindowGuard`, re-validated after, twice, the apply/write-back/tie seams re-deciding through its `StillCurrent`) is enforced in code here, not by comments at a call site. The verdict is assertable at the module interface without a widget instance, a render tick, or a host gate (`WeatherFetchFlowTests`). |
| **WeatherDisplayState** | The widget's gated display state (Widgets): the single gate, the snapshot state, the resolved-identity value (folded in from the deleted `WeatherResolvedIdentity` module, the shared `WeatherResolutionState` and the pending write-back live here directly), the last-success stamp, and the version-gated forecast render copies, every read and mutation under the SAME lock, so the "one consistent view" is a type, not a discipline repeated at every call site. The widget's `IWeatherFetchHost` seam bodies and the render tick's lock region are forwards over the module (`TryApply` / `TryApplyTie` / `QueueLabelWriteback` / `TakePendingWriteback` / `Invalidate(kind)` / `CaptureRenderView`), and the flow's test host wraps the SAME module, the flow's guarantees are pinned against the production gate shape, not a mirror. The write-back TAKE runs under the gate (a queue landing between the take's read and clear is unrepresentable) and re-decides eligibility there, the `WritebackEligible` policy (a non-empty name, the CustomLabel veto, the no-op-write veto) is the one spelling, evaluated at the queue AND the take, so the old gap (a CustomLabel set between the queue and an ungated flush check sailing through the flush) is unrepresentable: a veto refuses AND keeps the value queued (a "not yet", never a "never", the next frame re-decides against the current host facts); the Identity read hands out the immutable `WeatherResolutionState` record (its transitions run only through the gated members), and the last-success stamp resolves from an injected live-clock seam at stamp time (a test clock swap is observed). The module is parameterized by an injected neutral-location label (stored as a field, not a hardcoded client const) that `TryApplyTie` honors for a blank query, the seam is truthful, pinned by the test host injecting a distinct label. The tie reset bumps the data version AND the forecast version monotonically, a re-apply landing on a previously rendered forecast version would make the capture's copy-skip reuse the previous city's forecast lists under the new city's header (the no-capture collision is pinned). `CaptureRenderView` derives the key's `LocationSet` from the location's emptiness (a location edit with no data-version bump must still rebuild the render model and flip the subtitle guidance), and its wide positional signature is deliberate, one production call site, the fields are plain inputs, and a snapshot record mirroring the key's property half would duplicate the key in miniature. Pinned at the module interface without a widget instance, a fetch, or an HTTP stub (`WeatherDisplayStateTests`). |
| **WeatherFetchFlowOutcome** | The fetch flow's per-fetch verdict union (Widgets): `Applied` / `AppliedTie` / `DroppedStale` / `Skipped` / `Cancelled`: what `WeatherFetchFlow.RunFetchAsync` (the widget's `FetchLiveWeatherAsync` forwards to it) actually did with a fetch's outcome: `AppliedTie` (ADR-0009) is the tie's named apply (the tied candidates populated the dropdown, the data state reset to its placeholder, the queried name became the header, no snapshot), so the flow is assertable without polling side effects. |
| **WeatherGeocoder** | The geocoding transport layer (Widgets): Open-Meteo/zippopotam HTTP legs with bounded reads and per-leg deadlines (the transport is a LIVE provider over the client's one `TestHttpClient` seam, resolved at request time, so a test's transport swap is observed on the next request and there is no sync step to drift), tolerant candidate/ZIP parsing, and the coordinate/postal/pick/city entry points (the resolution ladder: explicit coords → `"lat,lon"` pair → postal → warm pick → city): the postal leg runs zippopotam FIRST (60+ route countries, not US-only; zippopotam 404s on unsupported routes/full GB-CA codes) and falls back to the geocoder's own postal search HINTED-THEN-BARE (a leg that answers stops the sequence, and a hint the zippopotam index lacks must not leave the user with no weather); the pick-path fast path resolves a cached dropdown pick to its coordinates with ZERO HTTP (a pick absent from the cache falls through to the city leg, which re-geocodes and re-checks the pick through the resolver's exact-name + suffix/hint consistency rules); the city leg shapes the pick list (exact-name candidates only, postal queries keep every candidate, since the code matched their postcode index, not their names). Delegates every ranking/decision rule to `WeatherLocationResolver` (a leaf utility the client also calls directly for the forecast URL and the postal route decision). |
| **WeatherFetchResult** | The fetch-outcome union (Widgets): `Fetched`/`Tie`/`Throttled`/`InFlight`/`Failed`/`Stale`: a fetch result without a snapshot is unrepresentable, and a tie without candidates is unrepresentable (ADR-0009: `Tie` carries the tied candidates + the query key the geocoder refused to break, the widget's Location Match dropdown rides it, so a tied city is a pick to be made, not a dead end; the snapshot exists only on `Fetched`); the fetch flow distinguishes "try again now" (`Stale`) from "keep what you have" (the rest). |
| **WeatherInvalidation** | The resolved-identity invalidation rule (Widgets): the ONE property → drop-granularity map (`KindForProperty`: the `LocationMatch` pick → `Coordinates`, every other resolution input → `Location`, display-only properties → `None`) that the widget's `OnPropertyChanged` routes every resolution-input edit through, so the client's `WeatherFetchControl` twin and the widget's `WeatherDisplayState` twin can never drift on what an edit drops, `Coordinates` voids the resolved name/population (the widget twin's pending label write-back included, the client twin's identity query + throttle reset) but KEEPS the geocode candidates on both twins (a pick resolves against the candidates it was offered from); `Location` voids the WHOLE identity (candidates included) on both twins. The identity value itself is the shared `WeatherResolutionState` record (candidates, resolved name, population) both twins hold, and the single drop rule `Drop(kind, state)` applies the declared granularity to that value (None is the identity function; Coordinates drops name + population and KEEPS the candidates; Location empties it to the one `Empty` state). The twins' transitions route their shared part through it, then clear their OWN unique fields (the client's coordinates + query + throttle, the widget's pending write-back). The twin-equivalence pin drives both twins through every kind and compares their resulting identity values structurally (plus the pure `Drop` pins per kind), so a new resolved field added to the record is caught the moment a twin's transition forgets to route it through the rule (`WeatherInvalidationTests`). |

### Touch Input

| Term | Definition |
|------|-----------|
| **Hardware touch** | Physical touch from the display, polled by `DisplayDeviceEngine` at 16ms in direct-USB mode, normalized once via `TouchReport.ToEventType`, and raised through `OnTouchEvent` to MainWindow, which enqueues it on the drain queue (one drain scheduled per burst) and feeds it IN ORDER into the input controller, because the gesture machine needs the full ordered Down/Move/Up sequence, not just the last point (the in-order feed is pinned at the window seam, `DeviceTouchDrainTests`). |
| **Widget touch** | Local-coordinate touch events delivered to `IModernWidget.OnTouch()` after compositor hit-testing. |
| **Gesture** | Input-sequence interpretation shared by the USB-direct and mouse paths: one `GestureInterpreter` state machine (swipe 70/80 px for page nav, arrow-tap 60/964 edge zones × 200–400 y-band for page switch, tap for widget touch). The mouse feeds the same Down/Move/Up vocabulary through `InputController.Feed` directly; edit-mode widget manipulation gates the machine in the mouse handlers (widget routing suppressed in edit mode, page actions still applied). |
| **InputController** | The single input module (App) behind which the gesture machine, its outcome application, the routing veto, widget routing, and edit-mode manipulation decisions (drag/resize/icon-grab + snap-to-grid math) all live. Callers only feed `Down/Move/Up` coordinates + the source (Press/Move/Release are source-aware); page-switch UI work stays in MainWindow behind one navigation seam. The desktop edit-mode read is the controller's own injected probe, read per sample and derived from the source, so the veto can't be passed wrong at a call site: the mouse path carries the desktop edit-mode flag (authoring input, presses manipulate), the physical display never does (runtime input, hotkeys fire on the device even in edit mode), and the per-sample derivation (never cached at construction) is pinned by test (`InputControllerTests`). |

### Data Flow

1. **Render loop**: MainWindow tick → `SkiaFrameCompositor.Compose()` → `FrameDelivery` (encode + pool + pace) → `DisplayDeviceEngine.SendFrameBytes()` → `IDisplayTransport.SendFrame()`
2. **Touch flow**: `DisplayDeviceEngine.TouchPollTick` (16ms PollLoop, reads `ReadTouch()`, normalizes raw byte → `TouchEventType` via `TouchReport.ToEventType`) → `OnTouchEvent` → MainWindow → `SkiaFrameCompositor.RouteTouch()` → `IModernWidget.OnTouch()`
3. **Sensor flow**: `LhmSharedMemoryReader` (App, reads LibreHardwareService shared memory on the 1s `PollLoop` shape) → `LhmSensorStore.UpdateFromDto()` (static cache) → `HardwareMonitorWidget.Render()` reads snapshot
4. **Frame-time flow**: PresentMon producer (ADR-0003: `pmOpenSession` → `pmStartTrackingProcess(pid)` → dynamic-query poll on the 1s `PollLoop` shape) → `FrameTimeStore.Update()` (static cache) → `FrameTimeWidget.Render()` reads snapshot

### Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| Synchronous transport interface | USB I/O (WinUSB/LibUsbDotNet) is inherently blocking; fake async adds no value and forces sync-over-async bridges |
| Static stores with LastUpdate freshness | Widgets are instantiated via reflection (parameterless ctor) and can't receive injected dependencies; static stores with staleness tracking are the pragmatic solution |
| Telemetry DTOs in Sdk | `SensorSnapshotDto`/`SensorReadingDto`/`FrameTimeSnapshotDto` live in the lowest common layer so every project shares one mailbox format (the Service.Contracts assembly was removed with the service, ADR-0005) |
| FileLog in Sdk | Shared file logging utility placed in the lowest common layer so all projects can log to `display_device.log` without circular dependencies; its `RotationCapBytes` is the one shared rotation bound (the App's crash log rotates at the same cap). Writes are cadence-flushed (8 KB / 250 ms) and the App's `Exit` handler does the one final `Flush`, so the last lines, including the shutdown standby verdict, always land at exit. `FileLog.Write` is the one line-policy owner (it applies `LogLine.Sanitize` once per line, so every producer lands a well-formed line without spelling the rule) |
| Widget-per-file convention | Each widget class lives in its own `.cs` file with its `[WidgetMetadata]` attribute; the catalog is discovered by scanning the assembly. One type per file also holds for the Sdk contract, `IModernWidget`, `ModernWidgetBase`, and `IWidgetActionInvoker` each own one file (split out of the former single `IModernWidget.cs`) |

## Architecture Decisions

| ADR | Decision | Rationale |
|-----|----------|-----------|
| [ADR-0001](docs/adr/0001-synchronous-transport-interface.md) | Synchronous transport interface | USB I/O is inherently blocking; fake async adds cognitive overhead and prevents compile-time detection of sync-over-async |
| [ADR-0002](docs/adr/0002-named-pipe-wcf-transport.md) | ~~Named-pipe WCF transport~~ **Superseded by ADR-0005** | The WCF pipe is gone with the Service (ADR-0005); kept for history |
| [ADR-0003](docs/adr/0003-presentmon-service-for-frame-time.md) | PresentMon Service as frame-time source | Replaces the in-house ETW reader; Intel's LocalSystem service + named-pipe client matches the non-elevation goal with no custom ETW capture to maintain |
| [ADR-0004](docs/adr/0004-librehardwareservice-shared-memory-for-sensors.md) | LibreHardwareService shared memory as hardware sensor source | Replaces the in-house WCF sensor reader; LHS's LocalSystem service + mutex-guarded shared-memory maps match the non-elevation and low-overhead goals with no custom hardware-polling code to maintain |
| [ADR-0005](docs/adr/0005-remove-windows-service.md) | Remove the ModernWigiDash Windows Service | Once telemetry came from PresentMon/LibreHardwareService and the app owned the USB device directly, the Service and its WCF pipe were dead weight, a whole project, a named-pipe attack surface, and install machinery to maintain |
| [ADR-0006](docs/adr/0006-stale-identity-invariant.md) | One owner of the weather stale-identity invariant (`WeatherQueryKey`) | The rule "never apply weather resolved for a different place than the UI shows" was spelled 4+ ways (client capture window, cache-load stamp compare, widget return→apply re-check) and held by comments alone with no test surface. `WeatherQueryKey.Build` is the only key construction and `SameKey` the only predicate, so every guard site routes through one owner with a direct test surface |
| [ADR-0007](docs/adr/0007-weather-fetch-flow-module.md) | One fetch-flow module owns the weather fetch sequence (`WeatherFetchFlow`) | The capture window, the post-await drop gate, the drop-and-refetch routing, the write-back gating, the cadence gate, and the boot-load rollback were spelled across five widget methods, held by comments, and testable only through a live widget; the module enforces the sequence in code and exposes it as one interface (`CanFetch` / `RunFetchAsync` / `RunBootLoadAsync`) the widget forwards to, so the ADR-0006 predicate absorbs the old widget's second inline identity compare and the whole flow is pinned without a widget, a render tick, or the widget's gate |
| [ADR-0008](docs/adr/0008-typed-weather-fetch-host-seam.md) | The weather fetch flow's host seam is typed (`IWeatherFetchHost` + `WeatherApplyRequest`) | ADR-0007's own Negative, the ten-delegate bag was a discipline, not a type: a named seam gives the host contract a single spelling (and a test-double surface) and the apply payload a name, so a new payload field is a named addition to the record instead of a seven-positional-argument signature change on both sides |
| [ADR-0009](docs/adr/0009-weather-tie-outcome-carries-candidates.md) | The weather tie outcome carries its candidates (`WeatherFetchResult.Tie` + `AppliedTie` + `TryApplyTie`) | The ambiguity gate is load-bearing, a bare "Berlin" must never guess a city, but the tie's verdict collapsed into bare `Failed`, so the widget's Location Match dropdown (the documented escape route) was EMPTY exactly when it was needed: the candidates sat in the client twin where no display could reach them. A first-class `Tie` arm (no snapshot; candidates + the ADR-0006 query key) makes the tie assertable at every module boundary and populates the pick list on the first fetch; the escape route then rides the existing zero-HTTP pick path |
| [ADR-0010](docs/adr/0010-format-gate-does-not-police-line-endings.md) | The format gate does not police line endings (no `end_of_line` pin in `.editorconfig`) | `.editorconfig` pinning `lf` and `.gitattributes`' `text=auto` CRLF checkout contradicted each other: the gate failed with ~45,000 ENDOFLINE errors on every clean Windows checkout, and the noise masked 15 real violations. Line-ending discipline stays with git (`text=auto` normalizes to LF at commit); the gate measures only what git does not police: whitespace, final newlines, charset. Do not "fix" the missing pin back in |
