### Top findings

1. **Complexity hotspots in the App UI layer (Code Quality, A → keep A).** The largest production methods are in the window: `InspectorPanelRenderer.Render` (CC 19, Inspector/InspectorPanelRenderer.cs:66), `DialogHost.ShowIconPicker` (CC 19, DialogHost.cs:196, 178 lines), `PresentMonApiProbe` ctor (CC 18, PresentMon/PresentMonApiProbe.cs:38), and `NowPlayingPresentation.FriendlyAppName` (CC 18, an 11-entry lookup map, NowPlayingPresentation.cs:30). If the slim-down program wants one refactoring target, `ShowIconPicker` (178 lines, CC 19) is the biggest. Effort: half a day for the top two.
2. **Test coverage has no line-level evidence (Test Coverage, B).** The 42% structural name-match (155/365 production types with a name-matching test class) is a lower bound — the suite is behavior-driven (1610 methods, 182 classes, per-module test mapping documented in CONTEXT.md), but no runtime-coverage artifact exists in the repo. Adding one `dotnet test --collect:"XPlat Code Coverage"` baseline run would turn this grade from inferred into measured. Effort: ~1 h (tooling) — note it also serves the slim-down program as a regression floor.
3. **Four of five production projects do not emit XML docs (Documentation, B → A path).** Only `ModernWigiDash.Sdk.csproj` sets `GenerateDocumentationFile` (225 documented members emitted); Core, Hardware, Widgets, and App rely on inline `///` comments (6,380 doc lines) with no machine-readable output. Enabling the flag on Core/Hardware/Widgets would surface undocumented-public-API gaps at build time. Effort: ~1 h + fix the resulting gaps.
4. **12 production methods at CC ≥ 15 (review list).** Beyond finding 1: `WeatherFetchFlow.RunFetchAsync` (CC 16, WeatherFetchFlow.cs:65, 153 lines), `WeatherClient.FetchCurrentAsync` (CC 16, WeatherClient.cs:151), `FrameEncoder.ConvertToRgb565` (CC 16, Transport/FrameEncoder.cs:27), `AudioSampleConverter.Convert` (CC 16, AudioSampleConverter.cs:20), `WeatherLocationResolver.ScoreSuffixMatch` (CC 15, WeatherLocationResolver.cs:465). All are pinned by tests, so splitting is low-risk. Effort: 2-3 h if all.
5. **CONTEXT.md test count drift (Documentation).** CONTEXT.md cites 1614 unit tests; the current measured count is 1610 `[TestMethod]`/`[DataTestMethod]` attributes. Small drift, but the slim-down program should keep the cited number evidence-based (measured, not recalled). Effort: minutes.
6. **Worktree hygiene (process).** 3 untracked slim-down artifacts predate this report: `.audit/`, `docs/reports/slim-baseline-packages-20260821.md`, `docs/superpowers/plans/2026-08-21-global-usings-slim-modern.md`. Commit or tidy before the next phase so the baseline is clean. Effort: minutes.
7. **No action — triaged signals.** The `async void` handler, the shared `HttpClient`, and the 10 best-effort bare catches are all documented, guarded, and justified (see triage table); the synchronous transport and static widget stores are deliberate invariants (ADR-0001, CONTEXT.md) and were excluded from all grades.
