Problem

WeatherFetchFlow is the cluster’s deep module — but its interface is the widest in the cluster: a 10-parameter constructor whose apply param is a 7-arg positional function that serves two different call shapes (fetch path passes null version, boot path passes the captured version), and three anonymous delegates that only make sense with the host’s _forecastGate. The flow even reads the client’s raw timestamp (its own cadence leak, card 4) and the identity module’s candidates list through the bag.

Solution

Replace the delegate bag with one named host seam: a small interface the widget implements (named members with the gate discipline documented per member) and one apply-request record that replaces the 7-positional-arg function. The flow keeps its two entry points and its modules; the host adapter owns the gate wrap in exactly one place, and the test host becomes an adapter over the same seam — exact member shape is the grill’s job, not the report’s.

Wins

  • locality: the gate discipline is one named member, not three comment spellings
  • the apply request value is shared by flow, widget, tests — one spelling per field
  • leverage: flow interface drops 10 params → 3; new flow behaviour costs zero host wiring
  • tests: host-adapter fidelity is pinnable without a render tick or HTTP stub
  • the _identity.Candidates peek and the client-sentinel read (card 4) both lose their seats
  • ADR-0007’s negative (“a discipline, not a type”) becomes a type

Not an ADR conflict. ADR-0007 decided who owns the sequence (the flow) and deliberately left the host seams implicit — its Consequences/negative section names the open debt. This card completes that seam, it does not reopen the ownership decision.

2 · Lift the render-model build out of the widget

Worth exploring in-process

ModernWigiDash.Widgets/WeatherForecastWidget.cs (EnsureRenderModel 553–645, Render 340–413) ModernWigiDash.Widgets/WeatherRenderModel.cs ModernWigiDash.Tests/WeatherRenderModelTests.cs · WeatherForecastWidgetTests.cs

Before — the build is a 93-line private method inside the render tick

Render() — 74 lines, widget

UI-thread write-back flush RequestRefresh() — the cadence gate kick gated forecast-list copy Scale() + ComputeHeader() ← computed here

EnsureRenderModel — private · 93 lines · no covering tests at any interface

Scale() + ComputeHeader() ← again, same bounds, same frame WeatherPresentation.Build(display input) header: uppercase + font measure + truncate pills: MeasurePillWidths 11-field key record + cache slot

what goes into the key, how the display input composes, and the per-frame allocation discipline all live here — assertable only through a live widget render.

title + unit badge paint mode dispatch → renderer (5 layout modes)

After — one build module behind a small interface

Render() — thin: flush · refresh kick · gate-read · paint · dispatch

render-model build module — deep: one build call, whole policy inside

input: a value-snapshot of the display state (consistent view) + the property snapshot + bounds

Scale + ComputeHeader — once per frame Presentation.Build · truncate · pill widths key record: which inputs rebuild the model

house-pattern precedent: FrameTimeSnapshotFactory — “the only place the snapshot gets shaped, extracted so the conversions are directly testable.” The weather cluster is the one deviant.

widget keeps: gate read + the cache slot (the _renderModel field)

Problem

The display path was deepened all the way down — layout modes, display rules, the key record, the apply policy are all modules with their own tests — except the composition: which state fields and property fields feed the key and the display input, and the header truncation + pill-width derivation, sit in a private widget method with no test surface. The key’s record is pinned component-by-component in WeatherRenderModelTests; the build that populates it is not pinned anywhere at an interface. And the 30 FPS tick computes the header geometry twice per frame (Render and the build), because two call sites each reach for the layout module.

Solution

A build module — a factory on or beside the render model — that takes a value-snapshot of the display state plus the property snapshot and bounds, and returns the model-or-reuse decision (with the key). The widget’s render tick shrinks to: read the state under the gate, call the build, paint. The geometry is computed once, inside the module, per frame.

Wins

  • locality: “which inputs change the formatted strings” is one module’s interface, not a private method’s comments
  • tests: key-field coverage and display-input composition pin at the build’s interface — no live widget, no render tick
  • the per-frame double geometry compute collapses to one site (30 FPS path, allocation discipline)
  • leverage: a new display field touches the input shape + the model in one place
  • deletion test: deleting the build method concentrates ~93 lines of policy inside the render tick; as a module it earns the seam

ADR note. No ADR covers the model build — CONTEXT.md names the render model and its key but the build site is the widget. This is the same deepening shape the cluster already accepted for the fetch path (ADR-0007: “the widget keeps only host concerns”).

A new resolved field is added to the value and to one drop path, and the pin degrades from “both twins agree” to “the value’s drop is right.” The twins’ genuinely different state (pending writeback vs. throttle + identity query) stays with each. Honest caveat: the duplication cost today is managed — the twins are small, the field set is stable, and the pin is explicit.

Problem

The cluster’s mutable identity state is spelled twice with parallel invariants. Every edit kind clears the same fields in two modules through two method pairs whose only enforcer is the twin-equivalence test. When the field set grows (a new resolution output, a new pending piece of state), the maintenance cost lands in two places at once.

Solution (if pursued)

Extract the shared fields into one resolution-state value whose drop-per-kind is the single implementation the invalidation rule points at. Both twins store it; each keeps its delta. The pin survives as a belt-and-braces check but is no longer load-bearing.

Wins — if the field set keeps growing

  • locality: a new resolved field exists once, with one drop path
  • the invalidation rule and its state finally live in the same place
  • tests: drop-per-kind pins the value, not two twins

Deletion test on today’s twins: deleting either twin re-concentrates its state in the widget or the client — both earn their keep. The candidate is about the shared half of what they hold, so the badge stays Speculative until a concrete field-set growth shows up.

ADR note. The twin design is deliberate (CONTEXT.md names both; ADR-0006’s alternatives explicitly rejected moving the key into the fetch control). This card does not re-design the twins — it shrinks the duplication inside them. Surface it only because the drift cost is real, not because the current state is broken.

HasFetched is a client fact: “has a fetch stamp been set.” Today the flow learns it by comparing the client’s raw timestamp against DateTime.MinValue — a storage detail crossing the seam — and reads it through two separate single-door pass-throughs whose only production caller is the flow.

After — one named predicate

  CL2["WeatherClient"] -- "HasFetched — named predicate" --> F2["WeatherFetchFlow.CanFetch"]
  F2 -- "window check stays: IsFetchWindowElapsed" --> V2["static-snapshot veto

One-line change on the client surface (this cluster’s own history — “narrow the WeatherClient interface” — points this direction). The sentinel vanishes from the caller’s vocabulary; the placement of the cadence gate (ADR-0007: it lives in the flow) is untouched — the flow just stops reading implementation facts to implement it.

Wins

  • locality: “has the throttle ever been stamped” is one client fact, one spelling
  • the interface the flow must know loses a raw timestamp + a sentinel comparison
  • rides along with card 1 if that seam is re-cut anyway

Friction log — noted, not carded

  • The widget test file is a superset harness. WeatherForecastWidgetTests (1.2k lines, 27 tests) re-drives, through a live widget + HTTP stub and a 5-minute throttled client, races that WeatherFetchFlowTests already pins at the flow’s interface (in-flight edits, dropped-and-refetched outcomes, the boot-load race). Card 1’s typed seam is what lets the host wiring itself be pinned as a small adapter test — and lets the pure-duplicate race pins retire in favour of a fidelity pin (the host adapter is the mirror host).
  • The widget’s interface carries a test-forward row. Clock, TestHttpClient, ResolvedCityName, CacheFileName, FetchCompletedCount, plus _snapshotState / _renderModel / _pollCts / CacheLoadOverride — mostly for-wards to the flow, client and identity modules. Accepted cost of reflection-instantiated widgets (no injection); noted because a seam cut (card 2) or a shared test-surface module could shrink it, but the cost today is bounded and deliberate.
  • The inspector search seam is clean. Praise, for scope: IWidgetLocationSearch + EditorKind.LocationSearch keeps the App’s location-search editor generic over any widget; the weather knowledge (geocoding, the commit rule “a pick writes only the label”) sits in the widget, not the App. The one thin spot: the widget’s SearchAsync forward has no covering test (the geocoder’s search is tested through the client).
  • Two client interface members exist only for the flow. LastFetchTimeUtc and IsFetchWindowElapsed are single-door pass-throughs (the widget never sees WeatherFetchControl) — the single-door pattern is deliberate here; card 4 trims only the raw-state one.

Top recommendation

Give the fetch flow a typed host seam

Strong jump to card ↑

It is the one friction the cluster’s own ADR flagged and left deliberately: ADR-0007’s consequences end with “a discipline, not a type” — and that discipline is now spelled in three places (the flow’s docs, the widget’s constructor, the test host’s wiring) around a 7-positional-arg function that carries the cluster’s subtlest bugs (the capture window, the gate) as unnamed slots. Cutting one named seam with one apply-request value gives the flow a smaller interface and turns the mirror test host from a copied wiring into an adapter — leverage for every future flow change, locality for the gate rule, and a test surface where host fidelity stops needing a render tick. Cards 4 rides along if the seam is re-cut; card 2 is the safe second; card 3 waits for the field set to grow.
