Architecture review: ModernWigiDash

2026-08-23 · deepening candidates from a three-cluster walk (App, Widgets, Hardware/Core/Sdk) · hot spots weighted by 45 days of git history

module seam / comment-only link leak / untested / discarded deep module comment-only fact

Scope note: the weather cluster (ADR-0006 to 0009), the transport connect machine, and the log-line rules (LogLine/LogCadence) are already deep and are not re-suggested. The candidates below are the residual friction: facts held by comments, verdicts composed at several sites, and rules that live in the widget where no module owns them.

Make the startup order a named artifact

Strong in-process

ModernWigiDash.App/MainWindow.xaml.cs (ctor 124–315, _wired, guarded handlers) · MainWindow.Context.cs · 3 test hosts (DeviceTouchDrainTests, ProfileMutationContractTests, TeardownPlanTests)

Before: order held by four comments

1 · _usbDevice.Start() must precede InitializeComponent
2 · FrameDelivery, telemetry, catalog
3 · host modules (input, inspector, dialog) must precede the starter profile
4 · _profilePersistence.Load / starter Create()
↑ widget InitializeAsync runs synchronously here and calls back into the context (Twitch: RequestInspectorRefresh, ShowDeviceAuthorization)
5 · snap-to-grid resync must not arm a save: _wired still off
6 · pump, power, teardown hook
7 · re-assert IsEditMode Checkbox.Checked fired inside InitializeComponent
8 · _wired = true must be the last statement; 4 XAML handlers guard on it

The startup NRE this order prevents is documented at lines 167–172. No test pins any of the four facts; the three test hosts only exercise the happy path.

After: the wiring is the artifact

ctor: var plan = BuildStartupWiring()
↓

StartupWiring (one named artifact, the TeardownPlan image)

  • ordered steps: modules before profile load
  • null-safe context facade: pre-module callbacks are benign, not NREs
  • edit-mode + snap resyncs are typed steps, not trailing re-asserts
  • _wired guard set once, at the end, by the artifact
↓apply in order
test hosts assert the same plan (4 construction sites, one artifact)

Precedent already in the house: BuildTeardownPlan made shutdown “a named, testable artifact” (commit b3ef614), pinned by TeardownPlanTests.

Problem. The window's constructor holds four ordering facts that exist only in comments; the host modules are callback-safe only because of a construction order nothing enforces, and the historical bug class (startup NRE) is pinned by no test.

Solution. Make the startup sequence a named artifact the way teardown already is: an ordered, assertable wiring list over a null-safe context facade, so pre-module callbacks are benign instead of fatal.

  • • Ordering enforced, not commented
  • • The NRE class becomes unrepresentable
  • • Four construction sites assert one artifact
  • • Locality: startup knowledge in one module
