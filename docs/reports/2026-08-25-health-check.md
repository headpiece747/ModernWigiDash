## Top findings

1. **No runtime line-level coverage evidence (Test Coverage, B).** The 38.1% strict structural match (148/388 production types with a name-matching `*Tests` class) is a lower bound for this suite's style: it is module-driven (e.g. `WeatherFetchFlowTests` pins the fetch sequence; presentation modules are exercised through their widget's render tests), 1,798 test methods sit in 233 classes over 29,838 lines (test:src line ratio 0.98), and CONTEXT.md documents the per-module mapping. The rubric's percentage only measures one-class-per-type suites, so the strict number is reported as a lower bound, not a verdict. Carried open from 2026-08-21: one `dotnet test --collect:"XPlat Code Coverage"` baseline run would turn the grade from inferred into measured and gives the gate a regression floor. Effort: about 1 hour.

2. **Four of five production projects do not emit XML docs (Documentation, B to A path).** Only `ModernWigiDash.Sdk.csproj` sets `GenerateDocumentationFile` (219 documented members across its 35 public types, the cross-assembly contract layer). Core (108 summaries), Hardware (122), Widgets (698), and App (372) carry 1,300 inline `///` summaries with no machine-readable output, so their public API (24 + 3 + 73 + 3 types) has no mechanical doc-coverage check. Enabling the flag on those projects surfaces the gaps at build time. Carried open from 2026-08-21. Effort: about 1 hour plus fixing the resulting gaps.

3. **Eight hand-written production methods at CC >= 15 (Code Quality, review-only; keeps A).** `InspectorPanelRenderer.Render` CC 19 (ModernWigiDash.App/Inspector/InspectorPanelRenderer.cs:62), `PresentMonApiProbe` ctor CC 18 (ModernWigiDash.App/PresentMon/PresentMonApiProbe.cs:38), `WeatherClient.FetchCurrentAsync` CC 16 (ModernWigiDash.Widgets/WeatherClient.cs:141), `FrameTimeWidget.RenderTrackedView` CC 16 (ModernWigiDash.Widgets/FrameTimeWidget.cs:110), `FrameEncoder.ConvertToRgb565` CC 16 (ModernWigiDash.Hardware/Transport/FrameEncoder.cs:27), `AudioSampleConverter.Convert` CC 16 (ModernWigiDash.Widgets/AudioSampleConverter.cs:20), `WeatherLocationResolver.ScoreSuffixMatch` CC 15 (ModernWigiDash.Widgets/WeatherLocationResolver.cs:464), `ProfileOps.RehydrateWidget` CC 15 (ModernWigiDash.Core/Models/ProfileOps.cs:227). All are pinned by tests, so splitting is low-risk. New this round versus 08-21: `FrameTimeWidget.RenderTrackedView` and `ProfileOps.RehydrateWidget`; resolved since then: `DialogHost.ShowIconPicker` (was CC 19) and `NowPlayingPresentation.FriendlyAppName` (was CC 18). Effort: 2-3 hours if all.

4. **41 unused parameters, all delegate signatures (Dead Code, review-only; keeps A).** 27 in `MainWindow` (handler `sender`/`EventArgs` pairs), 10 in the `WinRtMediaSessionSource` WinRT adapters, 1 each in `PageTabsView`, `SystemPowerModeSource`, `DisplayDeviceEngine`, and the generated test SDK.
